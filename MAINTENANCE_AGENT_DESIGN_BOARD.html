2What shipped today

The tester's sideA REPORT tab on all 14 tester-facing pages. First-party, 13 KB, no CDN, no dependency on the app's own JavaScript — so it works identically on the marketplace, the admin tool, the legal pages and the nine adventure maps.

3The Path A / Path B boundary

Your adopted split. Everything the agent does eventually reduces to choosing one of these two, so getting the boundary right matters more than any other single decision.

Path A — mechanical

Fix it now, ship it through the gates, tell nobody.

  • Wrong copy, typos, labels
  • Configuration and flags
  • Logic bugs with a clear right answer
  • Anything with a tripwire test that proves it

Path B — design change

Write a dossier, batch it, never hotfix it.

  • Layout and new interface
  • Flows and journeys
  • Brand and voice
  • Anything three testers hit for the same underlying reason

5The eight decisions still open

Each carries my recommendation so you can settle it in a sentence. Open one at a time; nothing here is urgent before the 22 August rehearsal.

OPEN 1 · Can the agent close a fault the tester never confirms?

Today's intake introduces awaiting-retest — shipped and written to, but not confirmed from outside. Total autonomy says the agent decides; honesty says a fix we only verified ourselves is not verified. Testers will go quiet, so something must give.

Recommendation: after 7 days of silence the fault becomes presumed fixed, not verified — a distinct state — and the recurrence counter stays armed. If it comes back, it comes back to the same row with the same code and the count tells us we closed it too early.
OPEN 2 · What may the agent never touch on its own?

Doctrine says money, legal and safety escalate. Doctrine is not a control — a denylist in code is.

Recommendation: a hard path guard in the fix session: the Tuppence ledger, payment handlers, the authentication path, and the EULA/privacy surfaces are refused outright with a clear message, not merely discouraged. Everything else is fair game.
OPEN 3 · The escalation brief — the one thing you actually read

Stage 7 is the only place you appear in the whole loop, so its shape is the whole ergonomics of the agent.

Recommendation: one screen per issue — what happened, what I have already done (safest option, taken without asking), then two or three alternatives each as a single tick. You are never asked to approve an action; you are offered the chance to redirect one already taken.
OPEN 4 · How often does it wake?

Three scheduled sessions a day was the B2 sketch. A blocker filed at 09:05 waiting until 13:00 is a bad look during a launch month.

Recommendation: three scheduled runs, plus an immediate run when a blocker is filed — the intake already knows the severity at the moment of filing, so the trigger is free.
OPEN 5 · The recurrence threshold

The register says three recurrences after a shipped fix triggers a Path B dossier. Untested — three may be too patient for a launch month and too twitchy afterwards.

Recommendation: keep three, but let the month tell us. If the count reaches three on anything before 1 September, that fault is the first real test of the design lane.
OPEN 6 · What exactly does the kill switch kill?

One lever, two possible meanings: stop shipping, or stop everything.

Recommendation: the switch stops shipping only. Intake, acknowledgement and triage keep running — a tester must never hit a dead button because we paused the fixer.
RULED 7 · Who reviews the agent's work?

Your review-roles doctrine puts an Author, a Peer, QA, CM and a System Engineer on every design review. The agent is Author. GPT-5.6 is already appointed Peer.

Open sub-question: does the Peer review every autonomous fix, or only Path B design changes? Recommendation: Path B only — reviewing every typo fix would make the Peer noise, and the gates already are the review for Path A.
RULED 8 · When does the brain move off the subscription?

Ruled: scheduled Claude sessions for launch, re-bound to a server-resident worker once the rush subsides. The trigger was left as "a trickle", which is not a number anyone can act on.

Recommendation: re-bind when new faults fall below five a week for two consecutive weeks. Config-grade move, spine unchanged — exactly as ruled.
