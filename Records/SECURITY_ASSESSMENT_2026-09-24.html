Data & backups

C1Fixed & verified

Every nightly copy of the full user database and the prospect database (14 days, 31 files) sat in the public photo bucket, downloadable by date.

Moved to the private encrypted bucket, public copies deleted, nightly backup now private; Cloudflare's own logs show nobody but this assessment ever downloaded one (whole exposure window since 28 Jun).

H7Fixed & verified

13 ID documents and 1 certificate sat in the public photo bucket.

All 14 files (plus 7 unreferenced ones) moved to private server storage with an encrypted off-site copy; old public links now 404 and only the owner, an admin or an accepted-intro buyer can open them.

M9Fixed & verified

The only daily off-site backup was the public one; the encrypted backup had not run since the July baseline.

Daily encrypted off-site backup of both databases and the private documents.

L1Fixed & verified

340 old full-database copies lay in the app folder.

Moved into the root-only backup volume; the 194 newest stay for the lanes that make them.

Code

C2Fixed & verified

An upload's file name could climb out of the media folder and, with the app running as root, write any file on the server.

File names are reduced to safe characters and locked inside the media folder; the app no longer runs as root.

H1Fixed & verified

Seller-typed fields (title, suburb, photo link, intro message, JSON descriptions) could carry script that ran for every buyer and in the admin console.

One output filter in the security gate turns every such field into plain text and every photo field into a plain https link.

M7Fixed & verified

The Quick Listing app was served without any security headers, uploads could be served as web pages, and old TLS 1.0/1.1 was on.

Headers on /quick/, uploads sandboxed, TLS 1.2+ only, server version hidden.

L2Fixed & verified

The CityLauncher API map (/launch-api/docs) was public.

Closed (404).

L3In Q4 batch

Browser protection still allows inline script, so a future missed field could still run script.

Strict CSP added to the Q4 baseline batch as item 10.

Access & identity

C3Fixed & verified

CityLauncher let anyone on the internet stop or restart its services and read its city/KPI data.

Every CityLauncher route now needs the launch key or an enrolled device; the key was rotated.

H2Fixed & verified

The listing-AI service trusted a typed email, so anyone could read other people's AI reports and inputs, and spend their Tuppence once a key is placed.

Identity now comes only from the signed-in session; examples are curated fixtures only.

H9Fixed & verified

Sign-out left the session cookie valid for 180 days, sign-in links could be replayed, and closed accounts stayed signed in.

Live and tested end to end: a link works once, an 80-hour-old link is refused, and signing out ends the session.

M8Fixed & verified

SMS codes had no daily ceiling, the admin password had no platform-wide guess limit, and one redirect could leave the site.

Daily SMS ceiling, platform-wide admin guess ceiling with constant-time check, redirect closed.

M10Fixed & verified

While testing, one of my commands printed the CityLauncher launch key into this session.

Key rotated immediately; no other copy existed.

L4Accepted by you

Your root SSH key is stored without a passphrase in the Projects folder.

You chose no passphrase; the firewall only admits your home address.

Money & trust

H6Fixed & verified

Top-ups and plans were granted from what the payer wrote into the payment, not from what was actually paid.

A grant now requires a ZAR payment of at least the asked price.

H8Fixed & verified

The ID-verified badge was awarded at 60% AI confidence even when the document did not match the typed name.

The badge now needs the AI to report that the document matches the typed name and number; live.

M1Fixed & verified

A seller could vouch for herself (+12 trust points) by opening her own employer link in a private window.

A confirmation now counts only from a signed-in person who is not the seller, and a second one must come from a different person; live.

Server

H3Fixed & verified

The live app carried 58 known security bugs in its libraries, including image-parser memory corruption reachable by uploading a photo.

All production libraries upgraded; the vulnerability scanner now finds none.

H4Fixed & verified

All five apps ran as root, so any code hole meant control of the whole server.

All apps run as a limited user with hardened service settings.

H5Fixed & verified

The server accepted password logins for root, and root has a password.

Keys only; your key login was re-tested and works.

M5Fixed & verified

No host firewall, and two app ports listened on every network address.

Host firewall on (22/80/443 only) and both apps listen on the server itself only.

M6Fixed & verified

Operating-system security updates and a patched kernel were waiting.

Updates installed; reboot scheduled 03:30 SAST tonight with an automatic post-boot check I will read.

Edge & email

M2Fixed & verified

Anyone can send email claiming to be TrustSquare (DMARC 'none'), and a duplicate DNS record breaks the signature on all mail.trustsquare.co mail.

Duplicate record removed and all three domains (root, mail, learn) set to quarantine, with your OK; public DNS confirms it.

M3Fixed & verified

The server accepts traffic from any Cloudflare customer, which lets them get past your Cloudflare firewall rules.

A Cloudflare rule now adds a secret header and the server refuses anything without it (direct test 403, site via Cloudflare 200).

M4Fixed & verified

CityLauncher accepted forged email clicked/bounced events from anyone.

Every event must now carry Resend's signature (unsigned 401, signed 200).

L5Fixed & verified

Sign-in emails pass through Resend click tracking.

Single-use links make a tracked copy worthless after one click.
