- **SYNC-ORIGIN-1 + HARNESS-PARITY-1 (RUL-193, RG-0648):** the laptop and the cloud can no longer stop, wipe or overwrite each other's shipped work except by design. David, 1 Oct 2026: *"so that nothing is stopped, wiped, overwritten between the cloud and laptop, except if it is done by design."* That day's ship found three faults of one class: the laptop was 61 commits behind GitHub because cloud story walks ship straight to main/deploy; every nightly ship since 30 Sep had aborted on a check (the Postgres-readiness ratchet) that the cloud path never ran; and a laptop ship that changed `quick.html` without `genie/HARNESS.html` left the cloud gate refusing every branch until a cloud session put it right. Now: (1) one shared step, `scripts/sync_origin.py`, takes GitHub's newer commits in before ANY push — fast-forward or a normal merge, never rebase/reset/force; a conflict aborts with every file as it was, writes `SYNC_CONFLICT.txt` naming the files, and the push does not happen. It is called by `deploy_marketsquare.bat` (so `nightly_ship`/`nightly_tsl`/the host agent too), `release.bat` (now moves main and deploy together), `commit.bat`, `backup_marketsquare.bat`, `host_queue_worker.py` (git_push), `maintenance_agent.py` (now pushes main+deploy together), `deploy_web.py` and `request_deploy.py`'s relay (which also now runs the strict pre-deploy scan on the merged tree, as the laptop's hook does). (2) `nightly_checkpoint.bat` takes GitHub in every night at 05:30, shipped or not. (3) The pre-push hook refuses any push to main/deploy that would drop a commit GitHub holds, whatever lane runs it; `MS_ALLOW_OVERWRITE=1` is the only, deliberate, way past it. (4) The cloud ship job (`ops/cloudship/cloud_branch_ship.sh`, installed as `/usr/local/sbin/ms-cloudship.sh`) now runs the same strict `predeploy_check.py`. (5) `scripts/harness_parity.py --fix` copies whichever of quick.html / genie/HARNESS.html was edited over the other before a laptop ship, and `predeploy_check.py` flags DANGER if they still differ. (6) `check_deploy_drift.py` says "LIVE IS AHEAD by N commit(s)" instead of calling a behind laptop "local-ahead". Proven: sync_origin on a scratch repo (fast-forward, clean merge, conflict = rc 3 with files untouched and no merge left open, dirty overlap = rc 3 untouched); the hook refused a `--force` push over newer GitHub commits and allowed it only with the by-design switch; the new cloud gate passed a clean main and refused a tree with a 13th `INSERT OR IGNORE`; RG-0648 INFO, rulings_check RUL-193 reflected. Also: the 05:30 checkpoint now mirrors the laptop's own commits to GitHub main (never deploy), so cloud sessions start from what the laptop holds; a deploy request that finds live already matching is reported "NOTHING TO SHIP" instead of "SHIPPED rc=0" (it said SHIPPED at 17:35 that day while nothing moved); and nightly_ship quotes the drift line before piping it (DRIFT-PIPE-1 class). The Windows-side proof (host queue git_push) caught one fault in this change before it mattered: host_queue_worker.py looked for sync_origin.py in the project root instead of scripts/ -- the push stopped cleanly (nothing pushed, nothing overwritten) and the path was fixed. Cost model impact: none.
