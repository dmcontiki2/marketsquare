The one thing that confused you: there are TWO layers, and both use email

Temporary · gone 29 Aug

Layer 1 — The pre-launch GATE

A doorman on the whole building. Nothing to do with who you are — just "is the public allowed in yet?"
Cookie: ts_review · 365 days · HttpOnly, Secure
Signed with: _REVIEW_SECRET — a different key from admin, so a gate pass can never be read as an admin token
Grants: passage only. No identity, no admin, no superuser.
Enforced by: nginx auth_request on the catch-all (GATE-ENFORCE-2)
This is what locked you out. It disappears at the soft launch on Fri 29 Aug (RUL-001) — after that the gate simply is not there.
Permanent · the real product

Layer 2 — The user ACCOUNT

Your own key to your own flat. This is how every real buyer and seller signs in, forever.
Cookie: ts_user · 180 days · set only by /auth/verify
How: email a magic link at /auth/request-link, click it, account created on first use
Signed with: _JWT_SECRET (ACCOUNT-BIND-1, 5 Aug)
Grants: identity — your listings, your Tuppence, your intros
Untouched by last week's lockout and untouched by this fix. Per RUL-015, personal accounts stay email-linked; admin surfaces keep password/PIN.

The four doors through the gate — and which device each one opens

Break-glass

1. Reviewer code

Anyone you hand the code to
POST /review/login
Unlocks: the device you type it on
Checked: bcrypt against a hash held only on the server
Never leaves the server as plaintext. Revoke by replacing the hash file — no restart.
Same device only

2. Emailed link

Allow-listed testers
GET /review/enter?t=…
Unlocks: only the browser that opens the mail
Life: 30 min, single use
This is what caught you. Mail opened on your phone → the phone got in, the laptop stayed locked. Not a bug — it is what a magic link fundamentally is.
New · fixes it

3. Emailed 6-digit code

Allow-listed testers, any device
POST /review/claim-code
Unlocks: the device you type it on — read it anywhere
Life: 30 min, single use, 6 guesses
Same email as the link. Read it on the phone, type it on the laptop. This is the door that makes the gate device-independent (RUL-027).
New · never locked out

4. Admin password / PIN

You and your team
POST /admin/login
Unlocks: the device you type it on — plus admin rights
Grants: admin token and the gate pass
Previously blocked at the origin, which is why your correct password read back as "Incorrect reviewer code". Now the strongest credential opens every door.
All four share one rate limit: 8 attempts per 10 minutes per IP. All four hand out the identical ts_review cookie — one place in the code (_grant_review_cookie), so the doors can never drift apart.

What actually happens when someone opens trustsquare.co

1 · EDGE
Cloudflare
DNS, TLS, CDN, bot filtering. Never sees your credentials in the clear.
2 · ORIGIN GATE
nginx auth_request
Catch-all location / asks /review/verify: is there a valid ts_review cookie?
3 · DECISION
Pass or 401
No valid cookie → refused right here, before the app is even reached.
4 · APP
FastAPI
Serves the page and data. Identity (if any) comes from ts_user, separately.
Step 2 is the whole story of your lockout: the refusal happened at nginx, so the app never saw your password — and the screen guessed wrong about why.

Where AI actually sits — and what happens when a vendor dies

Zero AI

Entry, accounts, payments, listings, browsing

  • Every door above — plain crypto and email
  • User accounts, sessions, Tuppence balances
  • Paystack money path
  • Browsing, search, intros
Claude down = no effect whatsoever. So is OpenAI down. So is all three at once.
Uses AI

Content helpers only

  • Advert coach / listing write-up help
  • Photo anonymity scanning (vision tier)
  • Triage and market notes
Three-lane failover, and Claude is not the base lane:
BASE = OpenAI (all five tiers) → FAILOVER = Anthropic → SAFETY NET = Scaleway. A dead vendor degrades one helper feature, never entry.
So the thing you were worried about is already true by design: your users' access has never depended on Claude, or on any AI vendor. What depended on Claude last night was your ability to build — a different problem, and the one worth solving next.
