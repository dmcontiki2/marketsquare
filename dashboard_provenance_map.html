Why it kept happening — the real cause

1

Nothing enumerated the claims

There was no list of what the dashboard asserts. So the only index was your memory — which is exactly why it felt like you were the automator. You were the inventory.

2

Provenance was invisible

A live-fed chip and a hand-typed chip render identically. A wrong panel could only be caught by contradicting something you already knew. That is not a system — that is you doing QA from memory.

3

Every previous fix was instance-scoped

RG-0133, RG-0153, INSTRUMENT-TRUTH-1 and -2 each named specific elements and fixed those. All 68 hand-typed surfaces survived every one of them, because nobody had the list.

4

Failure rendered as success

The health dot was born green in the markup and never reset when the feed died — a green light burning directly above the words “Health check failed”. On the Orchestration page it is worse: any fetch failure renders as “Nothing waiting on you. ✨”.

The inversion

Before

  • Un-fed was silent and invisible
  • A green chip needed no justification
  • Staleness had no visual state
  • New hand-painted panels were free to add
  • Detection depended on David noticing

After

  • Un-fed is a build failure
  • A colour must be earned, dashed, or declared
  • Declarations carry an expiry date
  • A new unfed panel trips red the same day
  • Detection is machinery, not memory
