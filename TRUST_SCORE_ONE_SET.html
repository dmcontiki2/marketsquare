40 + 37 + 10 = 87, but the score is 80. Identity and Track Record cap at 30 each, so the sum is 40 + min(30, 37) + min(30, 10). The striped tail is the 7 points earned above the cap — real, and not counted. The panel now prints the capped subtotal and says what sits above it, so the visible list adds up to the headline.

Why the number used to move between screens

Before

The buyer-facing panel built its own SQL for identity and track record — a narrower set than the scorer read. Same seller, two pictures.

Then it wrote

It saved its answer to users.trust_score and to every listing that seller owns. Whichever screen you opened last won.

Now

One builder — _trust_evidence(). Both surfaces read it. The panel heals only its own category, and touches the stored score only when that IS the primary category.

What this does not change

The 60 in Quick is not a trust score. It is the listing score — how complete the advert is — and says "trust not opened yet" on the same line.
Two screens may still differ if they are scoped to different categories, because category credentials differ per advert — the panel now returns its category_key so that is answerable rather than mysterious.
A multi-category seller's public panel can read lower than before: it used to count earned credentials from every category, and now counts the advert's own, like the scorer.
Every prior ruling stands — base 40, the uncapped Local Market group, the per-listing mandate rule, penalties after the cap, and names-and-points-only anonymity.

The guard, so it is the last time

Two guards were already watching this area and neither could see this bug: one checks a headline against its own list, the other checks the arithmetic canon. Both passed while the panel counted a different set.

test_trust_one_set.py now fails the deploy if a second evidence builder appears, if the panel grows its own evidence SQL, if its writes stop being category-scoped, or if a group subtotal stops being capped. Run against the old file it fails 7 of 8 — including "the panel wrote a per-listing score to EVERY listing".
