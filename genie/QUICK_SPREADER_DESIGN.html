The spreader — three modes, one engine

MarketSquare · 14 September 2026 · design for review, nothing built

My opinion, plainly. The complexity you are sensing is real, but it is not in the number of features — it is in knowledge. A stateless snippet stays simple at any size; the moment it has to KNOW things it stops behaving like a snippet even while it stays small. So the question is not "how many features" but "how many facts must it hold". The answer is three: who you are, what you have already accepted, and what exists on the shelf. Three facts is not complexity. Branches are. Eight categories × two directions × three modes is forty-eight screens if you write it as branches, and it is one screen if you write it as data — which is exactly what the COMMS table already proved this morning. Keep doing that and this does not get complicated.

Three modes, and there are only ever threeDecided once at load by two questions: do I know you, and are you here to list or to look?

One tap engine underneath all three. The same renderer, the same category table, the same four taps. The ONLY thing that differs is what happens after the last tap, and that lives in one function — finish() — which is the single place in the whole app that knows a mode exists. If a future change needs a second place to know, that change is wrong.

The caps that stop the lookup becoming a second shelf
  • No narrowing chips, no sort, no paging, no map, no favourites.
  • At most five answers. If the right one is not in five, the question was wrong, not the list.
  • It may READ listings and WRITE nothing but a draft and a buzz — never a wallet, a score, an introduction or a profile. One line, and a script can check it by grepping the fetch calls.
  • An introduction is always a hand-over to the app. The spreader never holds Tuppence.
Turn "keep it small" into a number, so it is not a judgement call Measured today: 26 KB gzipped with the placeholder photos stripped — the 871 KB file is 90% photos. Proposed budget: 40 KB. Any feature that breaks it belongs in the app, not here. One line in the monthly sweep checks it, and the rule enforces itself instead of depending on discipline.

And one thing I would CUT, not add The spreader currently shows all three scores with full coaching (RUL-121). For a first-timer that is the most valuable screen in the product. For a member on the fast lane it is clutter he has read fifty times. Proposed: full coaching for a first publish, one line for a member — "listing score 60, +40 available" with a tap to see why. Same rule as everything else: the screen does not change, the data does.
